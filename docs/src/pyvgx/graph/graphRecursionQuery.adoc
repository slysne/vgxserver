[[neighborhood_recursion_overview]]
== Overview

Recursive search is a powerful feature for automatically exploring a graph to collect top matching items ranked by some scoring formula. For recursion to be efficient and successful in finding the best matches, the graph network must be constructed in accordance with some proximity metric where each vertex is connected to a small set of neighbors that are closely related in some way. It is usually desirable for such a graph to be strongly connected, where a path exists from any starting point to any other vertex in the graph.

A proximity graph using vectors to express similarity is a prime target for this type of recursive traversal. Such a graph is often a navigable nearest-neighbor construction with diverse local neighborhoods covering both short and occasional longer range hops. This allows efficient implementation of approximate nearest neighbor (ANN) search. The search condition is expressed as a probe vector and the recursion algorithm then explores the graph from a starting point (which can be any node), automatically finding paths to regions of the graph containing items whose vectors are most similar to the probe. 

.Approximate nearest neighbors (ANN) search 
[source, python]
----
g.Neighborhood(
    id = start_node,
    hits = 10,
    recursion = {
        'vector': probe_vector
    }
)
----

Neighborhood _recursion_ offers many optional control parameters for the recursive search process:

.Neighborhood _recursion_ control parameters, brief overview
[source, python]
----
g.Neighborhood(
  id = start_node,
  hits = 10,
  recursion = {
    # Main meta-parameter
    'bias': _B_,            # Main recall vs. speed control
    
    # Search target
    'vector': _v_,          # Probe for similarity search
    'filter': _f_,          # Arbitrary filter per visited node

    # Threshold control
    'heap_size': _H_,       # Size of top-k result heap
    'shadow_size': _S_,     # Length of threshold delay line

    # Limits
    'frontier_limit': _F_,  # Frontier queue size (non-beam)
    'expansion_limit': _E_, # Max number of node expansions
    'depth_limit': _D_,     # Max recursion levels
    'exec_ms_limit': _X_,   # Max execution time
    'visit_limit': _V_,     # Max node visits

    # Beam search
    'init_select': _i_,     # Number of initial entry points
    'beam_width': _W_,      # Initial beam width
    'beam_min': _L_,        # Min beam width
    'beam_max': _H_,        # Max beam width 
    'beam_curve': _C_,      # Beam narrowing bias
    'adaptive_taper': _T_,  # Use dynamic beam True/False

    # Optimizations
    'alpha': _a_,           # Depth discount (expansion thres.)
    'beta': _b_,            # Evals discount (expansion thres.)
    'gamma': _g_,           # Global offset (expansion thres.)
    'delta': _d_,           # Beam controller reactivity
    'epsilon': _e_,         # Score contrib. thres. discount
    'zeta': _z_,            # Smoothing factor for thres. EMA
    'omega': _O_,           # All optimizations weight

    # Traversal thinning
    'kappa': _k_,           # Arc trav. thinning above thres.
    'lambda': _l_,          # Arc trav. thinning rule

    # State management
    'reset_metrics': _r_,   # Reset counters from last query
    'reset_map': _R_        # Reset visited node map
  }
}
----

It is rarely necessary to use most of these parameters in a production setting, but they can be useful when developing proximity graph construction algorithms or for debugging. Most of the time the _bias_ setting is enough to choose a suitable tradeoff between recall and search speed. Its value ranges from -100 (max speed) to 100 (max recall) and automatically adjusts all other recursion controls. When a specific tuning parameter value is provided it overrides the default determined by _bias_.
